# WRAP 决策框架（中文）

基于奇普·希思与丹·希思《决断力》。与 [SKILL.md](SKILL.md) 结构对应。**中文回复必须使用中文 section 标题**，禁止混用 `Decision Statement` 等英文标题。

## 何时启用

- 工作/职业/生活中**较重要**的决定
- 多种障碍并存：思维狭隘、证实倾向、短期情绪、过度自信
- 用户提到 WRAP、决断力、Decisive、事前验尸、绊网等

**不适用 full 模式**：纯可逆小选择 → 即使用户调用 `/wrap-decision-making`，也走 **WRAP Lite**。

## 预检（在 W→R→A→P 之前）

按顺序执行；触发闸门则提前停止。

### 1. 不可妥协项（Non-Negotiables）

在拓宽选项**之前**，扫描并**排除**违反硬约束的方案：

| 类别 | 示例 |
|------|------|
| 健康与安全 | 有毒暴露、人身伤害、未处理医疗风险 |
| 法律与合规 | 违法、违约、监管红线 |
| 家庭与生活 | 不能在家办公、照护责任、签证/居住限制 |
| 财务生存 | 无确认收入则无法承受 |
| 伦理 | 用户绝不愿交换的核心价值 |

已确认或极可能违反 → **直接排除**，说明被哪条约束移除。状态**未知** → 走信息闸门，不得假设该选项安全。

### 2. 信息闸门

**触发条件**：给出可靠建议所必需的**关键约束**未知——如用户实际处境与题干选项不符、预算上限、健康暴露、可逆性、时间线、影响对象等。

**触发后**：

- 只输出**闸门模板**
- 提 **1–3 个问题**；多轮对话中**一次只问一个**
- **禁止**：建议、下一步行动、WRAP 分析、依赖未知事实的选项
- 用户答复后 → 重新预检 → 再选 Full / Lite

**不触发**：缺的是锦上添花的信息，Lite 仍可帮上忙（如午饭偏好）。

## 障碍诊断 → 技法绑定

诊断**主导障碍**，W/R 按表选技法并**限制产出数量**：

| 障碍 | W（上限） | R（上限） | 首选技法 |
|------|-----------|-----------|----------|
| 思维狭隘 | +1 新选项，1 个基准方案 | — | 消失选项测试 **或** 多目标追踪 |
| 证实倾向 | — | 1 条假设，1 条反证 | 考虑相反的情况 **或** 尝试（ooch） |
| 短期情绪 | — | — | A：一个距离问题（朋友/10-10-10/核心价值观） |
| 过度自信 | — | 1 个基本比率问题 | 缩小（外视）+ 事前验尸 + 1 个绊网 |

次要障碍：正文点出即可，不突破上限再加选项或问题。

## WRAP 流程摘要

每步标注：`已使用` / `已满足` / `已跳过`。

- **W**：最多 1 个 AI 提议（待确认）+ 1 个适用基准方案；不得提议违反不可妥协项或未经验证的方案
- **R**：1 条关键假设 + 1 条反证或最小实验；价格/政策/统计 → 标 **（待核实）** 或改为用户可执行的核实动作
- **A**：仅在有短期情绪或外部压力时触发；否则标 `已跳过`；只用一种距离技法
- **P**：1 个失败情景 + 1 个预警信号 + 1 个绊网；游行预演仅在确有超预期可能时使用

## 执行约束

1. 多轮对话中一次只问**一个**问题；首次给出建议前最多 **3** 个核心问题。
2. 步骤是后台检查表，**篇幅由模板约束**，不是步骤越多越好。
3. 不重复询问可推导信息；**多轮**只输出增量（见下）。
4. 建议须说明假设与不确定性；禁止保证结果。
5. 最终决定交还用户（接受/调整/拒绝），**不得替用户拍板**。

## 模式选择

| 模式 | 场景 |
|------|------|
| **闸门** | 关键约束未知 |
| **Lite** | 可逆小选择；或低 stakes 且路径清晰 |
| **Full** | 重要决定 + 约束已足够确认 |
| **增量** | 同一决策的第 2 轮及以后 |

**行数上限**：闸门 ≤15 行 · Lite ≤20 行 · Full ≤80 行 · 增量 ≤40 行

## 多轮规则

用户在同一决策下补充信息时：

1. 若框定变了 → **重写决策陈述**（如「已有合租办公室，问的是留还是退」）
2. 只输出**增量模板**，不重贴未变的 W/R/A/P
3. 仅修订受影响的步骤；建议/下一步按需更新
4. 新问题仍遵守「一次一个」

## 输出模板

### 闸门（信息不足）

```markdown
## 决策陈述
[暂定一句话，注明不确定点]

## 待确认信息
关键约束尚未明确，需要先确认以下几点才能给出建议：

1. [最重要的问题]
2. [可选第二问]
3. [可选第三问]

_确认上述信息后再继续 WRAP 分析，暂不给出建议。_
```

### WRAP Lite（≤20 行）

**保留**：决策陈述 · 一行障碍说明 · W（+1 选项或 1 基准）· R（1 反证）· A（一行或跳过）· P（1 绊网）· 方向（一句）· 下一步（一步）

**省略**：完整 WRAP 分析标题 · 状态字段 · 障碍 checkbox · 理由列表 · 关键取舍/最大假设/不确定性分块 · 游行预演 · 重开条件（除非必要）

```markdown
## 决策陈述
[一句话]

[一行障碍说明，如「思维狭隘——把午饭框成二选一。」]

**W**：[当前选项 + 最多 1 个 AI 提议，待确认]
**R**：[一个反证问题或微实验]
**A**：[一行距离视角，或「已跳过——事实驱动，情绪干扰小。」]
**P**：[一个绊网]

**方向**：[一句话；由用户决定]
**下一步**：[48 小时内可执行的一步]
```

### WRAP Full（≤80 行）

**保留以下全部区块**；各步仍遵守技法上限；行文从简。

**省略**：技法_catalog 复述 · 长选项清单 · 未标注的（待核实）数字

```markdown
## 决策陈述
[一句话]

## 障碍诊断
[活跃障碍，简要；不必用 checkbox]

## 不可妥协项
[已确认并用于过滤的约束，或「未发现」]

## WRAP 分析

### W — 拓宽选择空间
- 状态：[已使用 / 已满足 / 已跳过]
- 选项：[用户确认 + 最多 1 个 AI 提议，待确认]
- 基准方案：[一个适用的]

### R — 把假设放到现实中检验
- 状态：[已使用 / 已满足 / 已跳过]
- 关键假设：[一条]
- 反证：[一个问题或实验]

### A — 留出距离来考虑
- 状态：[已使用 / 已满足 / 已跳过]
- [核心优先级或一个距离结论——仅触发时填写]

### P — 做好出错的准备
- 状态：[已使用 / 已满足 / 已跳过]
- 事前验尸：[一个情景 + 一个信号]
- 绊网：[一个可观察触发器]

## 建议
**方向**：[明确建议]
**理由**（最多 3 条）：
1. ...
2. ...
3. ...

**关键取舍**：[...]
**最大假设**：[...]
**不确定性**：[高/中/低 + 原因]

## 下一步行动
- **行动**：[48 小时内可执行]
- **成功标准**：[...]
- **停止条件**：[...]
- **重开条件**：[...]
```

### 增量（第 2 轮起，≤40 行）

```markdown
## 决策陈述（更新）
[重新框定后的决定]

## 变化摘要
- [新事实及影响]

## 更新分析
[仅受影响的 W/R/A/P]

## 建议
[修订方向，或「不变」+ 理由]

## 下一步行动
[如有变化则更新]
```

## 外部信息规则

用户未提供的**价格、统计、比率、政策、第三方说法**：

- 一律加 **（待核实）**，**或**
- 改为：「核实方式：[用户 48 小时内可做的具体动作]」

不得把未核实数字当作建议的主要依据。

## 快速示例

- **闸门**：「图书馆还是租办公室？」——不知能否在家办公 → 只问_gate；禁止建议「家+图书馆」。
- **Lite**：「螺蛳粉还是江西米粉」→ Lite；10/10/10 压缩一行。
- **Full**：跳槽且薪资/行业/时间线已知 → Full；基本比率用待核实或核实动作。
- **增量**：补充 3D 打印废气 → 重写陈述；健康不可妥协；只输出变化部分。
